## 1. Why a 3-D representation?

An image policy sees a projection. It can overfit to textures, lighting, camera
pose and background colour. A point cloud represents the scene in metric 3-D
coordinates, which are invariant to colour and (if reconstructed in world
coordinates) to the camera pose used to capture it.

DP3 (Ze et al., RSS 2024) makes three choices:

1. **Point cloud observation** from depth + camera calibration.
2. **PointNet encoder** with max pooling, so the policy is permutation-invariant
   to point order.
3. **Diffusion policy** over action chunks, conditioned on the 3-D features.

The paper shows that a simple 3-D representation can outperform 2-D image
policies on many manipulation tasks, especially under visual distribution shift.
On our small planar task, DP and DP3 may both saturate; the point is the pipeline
and the robustness experiment, not a leaderboard gap.

## 2. Point-cloud pipeline

### 2.1 From depth to world coordinates

Chapter 02 implemented:

```text
pixel (u,v), depth d
  → camera coordinates  x = (u-cx)/fx * d,  y = -(v-cy)/fy * d,  z = -d
  → world coordinates   p = R_cam @ [x,y,z] + t_cam
```

The point cloud for the policy is sampled from this image:

- filter to the workspace;
- separate object points (`z > 0.004`) from table points;
- sample 80% objects and 20% table, with replacement if needed;
- return exactly `N=512` points.

Including a little table context helps the encoder understand where the arm and
puck are relative to the surface. Including too much table makes the object
points sparse; the 80/20 split is a practical compromise.

### 2.2 Normalisation

Use dataset statistics computed on the train split:

```text
p_norm = (p - pc_mean) / pc_std
```

`pc_mean` and `pc_std` are 3-D, computed over all training points. Do not centre
each frame: the absolute position of the puck relative to the workspace matters.
Do not normalise per-axis using that frame's own points either; that removes the
very information the policy needs.

### 2.3 Augmentation

For point clouds, use:

- random dropout of 5–10% of points (replace with a random existing point to keep
  `N` fixed);
- Gaussian jitter with `σ = 0.002 m`;
- random isotropic scale in `[0.95, 1.05]`.

Do **not** randomly rotate the point cloud about z: the actions are joint
angles, and a rotated scene is not equivalent under a joint-space action. If you
want rotation augmentation, you must rotate the action labels consistently (not
possible for joint angles without transforming the robot model), so skip it.

## 3. PointNet encoder

```python
# models/dp3.py (part 1)
from __future__ import annotations

import torch
from torch import nn

from imitation_learning_reproduction.models.common import mlp


class PointNetEncoder(nn.Module):
    def __init__(self, in_channels: int = 3, out_dim: int = 128,
                 hidden: tuple[int, ...] = (64, 128, 256)):
        super().__init__()
        layers = []
        last = in_channels
        for width in hidden:
            layers += [nn.Linear(last, width), nn.LayerNorm(width), nn.ReLU()]
            last = width
        self.mlp = nn.Sequential(*layers)
        self.proj = nn.Linear(last, out_dim)

    def forward(self, points: torch.Tensor) -> torch.Tensor:
        # points: (B, N, 3)
        h = self.mlp(points)          # (B, N, 256)
        h = h.max(dim=1).values       # (B, 256)
        return self.proj(h)


class PointCloudObsEncoder(nn.Module):
    def __init__(self, state_dim: int = 18, obs_horizon: int = 2,
                 point_feature: int = 128, state_feature: int = 64,
                 global_cond_dim: int = 320):
        super().__init__()
        self.obs_horizon = obs_horizon
        self.pointnet = PointNetEncoder(3, point_feature)
        self.state_encoder = nn.Sequential(
            nn.Linear(state_dim, 128), nn.SiLU(),
            nn.Linear(128, state_feature),
        )
        self.out = nn.Linear(obs_horizon * (point_feature + state_feature),
                             global_cond_dim)
        self.register_buffer("pc_mean", torch.zeros(3))
        self.register_buffer("pc_std", torch.ones(3))

    def set_point_normalizer(self, mean, std):
        self.pc_mean.copy_(torch.as_tensor(mean, dtype=torch.float32))
        self.pc_std.copy_(torch.as_tensor(std, dtype=torch.float32).clamp_min(0.01))

    def forward(self, state, point_cloud):
        # state: (B, To, 18) normalized; point_cloud: (B, To, N, 3) raw world coordinates
        b, to = point_cloud.shape[:2]
        pc = (point_cloud - self.pc_mean) / self.pc_std
        feat = self.pointnet(pc.reshape(b * to, *pc.shape[2:]))
        feat = feat.reshape(b, to, -1)
        st = self.state_encoder(state)
        return self.out(torch.cat([feat, st], dim=-1).reshape(b, -1))
```

Max pooling over points makes the encoder permutation-invariant. LayerNorm is
used instead of BatchNorm for the same reason as in the image encoder: evaluation
batches can be size one.

### Why PointNet here?

A transformer over 512 points is also valid and is what later 3-D policies use.
PointNet is smaller, easier to train on CPU, and makes the permutation-invariance
property explicit. The rest of the diffusion pipeline is unchanged.

## 4. DP3 policy

Reuse the diffusion scheduler and U-Net from chapter 11. Subclass the policy and
swap the observation encoder:

```python
# models/dp3.py (part 2)
from imitation_learning_reproduction.models.dp import DiffusionPolicy


class DP3Policy(DiffusionPolicy):
    def __init__(self, state_dim: int = 18, action_dim: int = 2,
                 obs_horizon: int = 2, horizon: int = 16,
                 down_dims: tuple[int, ...] = (64, 128, 256),
                 diffusion_step_embed_dim: int = 128,
                 num_train_timesteps: int = 100,
                 num_inference_steps: int = 10,
                 point_feature: int = 128, state_feature: int = 64):
        super().__init__(state_dim, action_dim, obs_horizon, horizon,
                         down_dims, diffusion_step_embed_dim,
                         num_train_timesteps, num_inference_steps)
        self.point_feature = point_feature
        self.state_feature = state_feature
        self.encoder = PointCloudObsEncoder(
            state_dim, obs_horizon,
            point_feature=point_feature,
            state_feature=state_feature,
            global_cond_dim=320,
        )

    def set_point_normalizer(self, mean, std):
        self.encoder.set_point_normalizer(mean, std)

    def _prepare(self, obs):
        state = obs["state"].float()
        if self.state_normalizer is not None:
            state = self.state_normalizer(state)
        point_cloud = obs["point_cloud"].float()
        return state, point_cloud
```

The parent `compute_loss` and `sample` call `self.encoder(state, image)`, which
now receives the point cloud. The method name `image` in the parent signature is
historical; in DP3 it is the point cloud. Rename it to `observation` in your
implementation for clarity.

The normalisation of points happens inside `PointCloudObsEncoder.forward`, so
`_prepare` returns raw world coordinates. Do not normalise twice.

```python
    batch = next(iter(loader))
    obs = {
        "state": batch["obs"]["state"].to(device),
        "point_cloud": augment_points(batch["obs"]["point_cloud"]).to(device),
    }
    loss = model.compute_loss(obs, batch["action"].to(device),
                              batch["action_pad"].to(device))
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()
    ema.update(model)
```

`augment_points`:

```python
def augment_points(points: torch.Tensor, drop: float = 0.08,
                   jitter: float = 0.002, scale: float = 0.05) -> torch.Tensor:
    # points: (B, T_o, N, 3), normalised or raw; keep N fixed.
    b, to, n, _ = points.shape
    x = points.reshape(b * to, n, 3)
    keep = torch.rand(x.shape[:2], device=x.device) > drop
    # Replace dropped points with random existing points.
    idx = torch.randint(0, n, (x.shape[0], n), device=x.device)
    batch_idx = torch.arange(x.shape[0], device=x.device)[:, None]
    x = torch.where(keep[..., None], x, x[batch_idx, idx])
    x = x + jitter * torch.randn_like(x)
    factor = 1.0 + scale * (2 * torch.rand(x.shape[0], 1, 1, device=x.device) - 1)
    x = x * factor
    return x.reshape(b, to, n, 3)
```

Augment only during training. Validate on the unmodified point clouds.

### Evaluation wrapper

```python
# eval/policies.py
from collections import deque

import numpy as np
import torch

from imitation_learning_reproduction.training.normalizer import (
    ActionNormalizer, StateNormalizer,
)


class DP3EvalPolicy:
    def __init__(self, model, stats, obs_horizon=2, execute_horizon=8,
                 num_inference_steps=10, device="cpu"):
        self.model = model.to(device).eval()
        self.device = device
        self.obs_horizon = obs_horizon
        self.execute_horizon = execute_horizon
        self.num_inference_steps = num_inference_steps
        self.history = deque(maxlen=obs_horizon)
        self.queue = []

        self.state_norm = StateNormalizer(
            torch.tensor(stats["state_mean"]), torch.tensor(stats["state_std"])
        ).to(device)
        self.action_norm = ActionNormalizer(
            torch.tensor(stats["action_low"]), torch.tensor(stats["action_high"])
        ).to(device)
        self.model.set_normalizers(self.state_norm, self.action_norm)
        self.model.set_point_normalizer(stats["pc_mean"], stats["pc_std"])

    def reset(self):
        self.history.clear()
        self.queue.clear()

    @torch.no_grad()
    def _sample(self, obs):
        self.history.append((obs["state"], obs["point_cloud"]))
        while len(self.history) < self.obs_horizon:
            self.history.append(self.history[0])
        states = np.stack([h[0] for h in self.history])
        clouds = np.stack([h[1] for h in self.history])
        state = torch.as_tensor(states, device=self.device).unsqueeze(0)
        cloud = torch.as_tensor(clouds, device=self.device).unsqueeze(0)
        return self.model.sample({"state": state, "point_cloud": cloud},
                                 self.num_inference_steps)[0]

    def act(self, obs):
        if not self.queue:
            chunk = self._sample(obs)
            self.queue = list(chunk[: self.execute_horizon].cpu().numpy())
        return self.queue.pop(0).astype(np.float32)
```

## 6. Robustness experiment

Evaluate DP and DP3 on the same seeds and variants:

```bash
for variant in default color light shift distractors; do
  uv run python scripts/evaluate.py --policy checkpoint \
    --checkpoint runs/dp/best.pt --obs-mode image \
    --visual-variant "$variant" --episodes 50 \
    --out "results/dp_${variant}.json"

  uv run python scripts/evaluate.py --policy checkpoint \
    --checkpoint runs/dp3/best.pt --obs-mode point_cloud \
    --visual-variant "$variant" --episodes 50 \
    --out "results/dp3_${variant}.json"
done
```

Expected qualitative pattern:

| Variant | DP | DP3 |
|---|---|---|
| default | strong | strong |
| colour | modest drop | almost no drop |
| lighting | modest drop | almost no drop |
| camera shift | larger drop | small drop |
| distractors | mixed | mixed |

DP3 is not automatically robust to **geometry** changes. Distractors add new 3-D
objects; a point cloud policy can be confused by them too. The experiment is
informative only if the point-cloud reconstruction is correct and the same
workspace filter is used for training and evaluation.

### Point-cloud visualisation

For a failing episode, plot the final point cloud from the top and side. Check:

- the puck is present and at the expected world coordinates;
- the arm is present;
- the goal marker is present;
- the camera-shift variant reconstructs the same world points, not a rotated
  frame.

If the point cloud looks wrong, fix calibration before blaming DP3.

## 7. Debugging

| Symptom | Likely cause |
|---|---|
| Point cloud empty or all zeros | Depth background/table filtering removed everything; check `z` range |
| Point cloud mirrored | Camera rotation transpose or y sign wrong |
| DP3 worse than DP on default | Point normalisation or sampling destroys object points |
| DP3 fails only on `shift` | Camera pose used for backprojection is the training camera |
| DP3 fails only on `distractors` | New geometry confuses PointNet; expected limitation |
| Training loss decreases, rollouts fail | Action normalisation or point-cloud channel order |
| PointNet output invariant to everything | Max pool collapsed; check feature norm and input scale |

### Sanity checks

1. **Permutation invariance.** Shuffle the 512 points and check that the encoded
   feature changes by less than `1e-5`.
2. **Known-object centroid.** Place a box at a known position, reconstruct the
   cloud, and check the centroid (chapter 02 test).
3. **Arm/puck separation.** On a reset, check that points above `z=0.04` include
   both the puck and the arm. If only the table is present, the camera framing or
   the object filter is wrong.
4. **Camera-shift consistency.** Backproject the same scene from `top` and
   `top_shift`; the puck centroid should agree within a few millimetres.

## 8. Tests

```python
# tests/test_dp3.py
import torch

from imitation_learning_reproduction.models.dp3 import DP3Policy, PointNetEncoder


def test_pointnet_permutation_invariance():
    torch.manual_seed(0)
    net = PointNetEncoder(3, 32, hidden=(16, 32))
    points = torch.randn(2, 64, 3)
    perm = torch.randperm(64)
    a = net(points)
    b = net(points[:, perm])
    torch.testing.assert_close(a, b, atol=1e-5)


def test_dp3_forward_shapes():
    model = DP3Policy(state_dim=18, action_dim=2, obs_horizon=2, horizon=16,
                      down_dims=(16, 32, 64), diffusion_step_embed_dim=32)
    obs = {
        "state": torch.randn(2, 2, 18),
        "point_cloud": torch.randn(2, 2, 64, 3),
    }
    actions = torch.randn(2, 16, 2)
    pad = torch.zeros(2, 16, dtype=torch.bool)
    loss = model.compute_loss(obs, actions, pad)
    assert torch.isfinite(loss)
    sample = model.sample(obs)
    assert sample.shape == (2, 16, 2)
```

`DP3Policy` inherits `sample` from `DiffusionPolicy`; `_prepare` returns the point
cloud, and `sample` passes it to the encoder. If the test fails with an image
shape error, the subclass did not override `_prepare` or the encoder.
